# GAIL Regional Portal — Frontend localization and review

## Changes applied

- Extended the existing `LanguageContext` Hindi dictionary and connected the remaining fixed frontend text to `t()`.
- Localized Admin section names, field labels, helper text, upload feedback, confirmation prompts, empty states, and common frontend messages.
- Used Hindi record fields (`nameHi`, `titleHi`, `descriptionHi`, etc.) for region and other dynamic labels where available, while preserving the existing English fallback.
- Added native `required` validation to Admin login fields and the Admin data-form text inputs, textareas, and required dropdowns.
- Kept the Organogram parent selector and pipeline selector optional because they are explicitly optional relationships. Supplemental media pickers remain optional where the existing workflow treats media as optional; the telephone-directory upload picker remains required. The parent-node and pipeline selectors remain optional relationships.
- Kept the existing route structure, API endpoints, layout, and primary UI behavior unchanged.
- Included a local SheetJS CE 0.18.5 bundle for the existing Excel preview import, since the uploaded frontend imported `xlsx` but did not declare it in `package.json`.

## Items to improve / verify

1. **Hindi content in the database:** The UI can translate fixed labels, but region/event/meeting/document records need their Hindi fields populated. Empty Hindi fields intentionally fall back to English.
2. **Backend validation:** HTML `required` is client-side only and can be bypassed. Apply matching validation in the API for required fields, dates, IDs, file references, and region assignments.
3. **Admin authentication:** The frontend stores the admin bearer token in `sessionStorage`. Consider an HttpOnly, Secure, SameSite cookie if the backend architecture supports it, plus token expiry/rotation, login rate limiting, and server-side authorization on every `/admin` endpoint.
4. **Upload security and limits:** Enforce file size, allowed extension and MIME type on the server; sanitize file names; prevent path traversal; and verify upload authorization. The upload helper currently relies on backend enforcement rather than checking size before sending.
5. **Telephone-directory download:** To reliably force a download, the file server should return `Content-Disposition: attachment` with a filename. Cross-origin downloads may ignore the frontend `download` attribute; Excel preview also needs appropriate CORS headers if files are hosted on another origin.
6. **Polling/network load:** `PortalContext` refreshes portal data every 20 seconds and the calendar polls every 30 seconds, in addition to focus refreshes. Consider a shared cache/query layer, pause polling in hidden tabs, and use backoff when the API is unavailable.
7. **Large data sets:** Admin record lists and some public lists are rendered in full. Server-side pagination/search will help as events, documents, gallery photos, and directory records grow.
8. **Accessibility:** The directory preview modal could be improved with `role="dialog"`, `aria-modal`, focus trapping/restoration, and body-scroll locking. Add consistent keyboard focus styles and verify every image has meaningful alt text.
9. **Error handling:** API-provided error strings are generated by the backend and may remain English; only frontend-owned fallback messages are translated here. Consider standardized error codes that the frontend can translate.
10. **SEO and metadata:** `index.html` has a single static title/description. Add route-aware document titles and descriptions, and review social preview metadata.
11. **Asset reliability/performance:** The logo is fetched from an external Wikimedia URL. Hosting an approved logo locally avoids a third-party dependency. Compress large photos and banner videos and use responsive image sizes.
12. **Dependency maintenance:** The bundled SheetJS module is version 0.18.5. Review and update the spreadsheet library periodically, preserving its license notice and testing Excel compatibility.

- Ran a SheetJS smoke test that created and read a small workbook successfully.
